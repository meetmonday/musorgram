# План реализации интерфейса Musorgram

## 1. Цель и границы

Сделать нативный клиент личных и групповых сообщений MusorBox для Android и
Linux. Визуальный ориентир — Telegram для Android периода 2015–2017 из
`reference.jpg`: синяя верхняя панель, плотный список диалогов, круговые
аватары, светлый узор переписки, белые и светло-зелёные сообщения, боковое
меню и плавающая кнопка нового диалога.

Референс задаёт визуальный язык, но не перечень функций. В интерфейсе не должно
быть активных элементов, за которыми нет метода в `API.md`.

## 2. Визуальная система

- **Основной синий:** `#5682A3`; тёмная системная панель: `#477695`;
  выделенный диалог: `#6D98B8`.
- **Поверхности:** белый список и редактор, входящее сообщение `#FFFFFF`,
  исходящее `#EFFDDE`, узор `assets/wallpaper.png`.
- **Типографика:** системный `Segoe UI` с fallback на Tahoma/Noto Sans/Roboto;
  размер основного текста 13–14 px, метаданных 9–11 px.
- **Геометрия:** высота панели 58 px, строки чата 68 px, аватары 39–46 px,
  скругление сообщений 4 px. Большие Material 3-карточки и чрезмерные
  скругления не использовать.
- **Адаптивность:** до 759 px список и переписка являются отдельными экранами;
  с 760 px показываются двумя колонками. На телефоне новое сообщение открывается
  круглой кнопкой поверх списка.
- **Фирменный элемент:** повторяющийся холодный узор переписки остаётся виден
  между компактными сообщениями и связывает мобильный и Linux-интерфейс.

## 3. Матрица возможностей API

### Реализуем в клиенте

| Возможность | API | Интерфейс / состояние |
| --- | --- | --- |
| Вход по URL, логину и паролю | `POST /api/auth/login`, `GET /api/me` | Отдельный токен приложения в защищённом хранилище; пароль не сохраняется — реализовано |
| Список личных и групповых чатов | `GET /api/messages` | Плотный список, превью, время, unread badge — реализовано |
| Локальный поиск по чатам | Данные списка | Строка поиска и `Ctrl+K` — реализовано |
| Поиск пользователя | `GET /api/messages/users` | Диалог нового сообщения — реализовано |
| Личная переписка | direct history / updates / POST | История, пагинация, отправка, optimistic UI — реализовано |
| Групповая переписка | group history / updates / POST | Участники, история и отправка — реализовано |
| Создание группы | `POST /api/messages/groups` | Название, поиск и выбор до 49 участников — реализовано |
| Вступление по приглашению | `POST /api/messages/groups/join` | Ввод полной ссылки или токена — реализовано |
| Realtime | `GET /api/messages/events` | SSE с переподключением и дозагрузкой updates — реализовано |
| Статус прочтения | `readThroughId`, `read` event | Одинарная/двойная галочка, unread badge — реализовано |
| Старые сообщения | `before=<olderBefore>` | Кнопка загрузки предыдущей страницы — реализовано |
| Изображения и альбомы | multipart в direct/group POST, media GET | До 10 изображений в одном сообщении, общая подпись, предпросмотр — реализовано |
| Аватары | URL в моделях пользователя | Сетевой и дисковый кэш, инициалы при ошибке — реализовано |
| Уведомления | События SSE | Локальные уведомления, пока процесс активен — реализовано |

### Поддерживается API, но остаётся следующим этапом

| Возможность | API | План |
| --- | --- | --- |
| Добавить/удалить участника | group members POST/DELETE | Экран сведений о группе с проверкой роли владельца |
| Заменить ссылку-приглашение | invite reset POST | Копирование и подтверждение сброса в сведениях о группе |
| Покинуть группу | group leave POST | Опасное действие с подтверждением для обычного участника |
| Удалить группу | group DELETE | Только владельцу, отдельное подтверждение |

Эти действия не нужны для воспроизведения трёх основных экранов референса и не
должны перегружать первую версию. Модель ответа группы позднее нужно расширить
полями `currentUserRole`, `ownerId` и `inviteUrl`.

### Не реализуем: API этого не предоставляет

- произвольные файлы и документы (изображения поддерживаются отдельно);
- голосовые сообщения и кнопка микрофона;
- стикеры как отдельный тип сообщения;
- секретные чаты и end-to-end encryption;
- каналы;
- адресная книга/синхронизация контактов и приглашение друзей;
- изменение профиля и аватара;
- индикатор «печатает…»;
- гарантированные push-уведомления при завершённом процессе (нужен серверный
  FCM/APNs, которого в API нет).

Форумные топики, комментарии и голосования из общего `API.md` находятся вне
задачи Musorgram: это клиент сообщений, а не полный клиент портала.

## 4. Экранная структура

```text
Телефон                         Планшет / Linux
┌──────────────────┐           ┌────────────┬─────────────────────┐
│ ☰  Musorgram  🔍 │           │ список     │ шапка переписки     │
├──────────────────┤           │ диалогов   ├─────────────────────┤
│ поиск            │           │ + поиск    │ история             │
├──────────────────┤           │            │                     │
│ список диалогов  │           │            ├─────────────────────┤
│              ✎   │           │            │ ввод / отправить    │
└──────────────────┘           └────────────┴─────────────────────┘

Боковое меню: профиль → новое сообщение → новая группа →
вступить в группу → настройки подключения.
```

## 5. Порядок работ

1. **Каркас и тема — готово.** Палитра, типографика, wallpaper, светлая/тёмная
   тема, мобильная и двухколоночная раскладка.
2. **Список чатов — готово.** Шапка, поиск, строки, счётчики, FAB, пустые и
   загрузочные состояния.
3. **Переписка — готово.** Шапка, история, разделители дат, пузырьки, статусы,
   пагинация и редактор текста.
4. **Навигация — готово.** Drawer в стиле референса; скрыты невозможные пункты
   Telegram (секретный чат, канал, контакты).
5. **Создание и вступление в группы — готово.** Валидация 2–80 символов,
   максимум 49 приглашённых, поддержка ссылки и чистого токена.
6. **Профиль, сведения и настройки — готово.** Read-only профиль, данные
   собеседника, состав группы и приглашение, состояние подключения, разрешение
   уведомлений и очистка локального кэша.
7. **Управление группой — запланировано.** Действия владельца и выход участника.
8. **Контроль качества.** `dart format lib test`, `flutter analyze`,
   `flutter test`; ручная проверка ширин 360, 600, 760 и 1280 px, светлой и
   тёмной темы, клавиатурной навигации Linux и сценария offline-cache.

## 6. Критерии готовности первой версии

- На телефоне внешний вид узнаваемо соответствует всем трём частям референса:
  drawer, список диалогов и переписка.
- Любая показанная основная кнопка выполняет поддерживаемое API действие.
- Ошибки `401/403/404/409/429` отображаются пользователю без потери введённого
  сообщения.
- После обрыва SSE клиент переподключается и запрашивает пропущенные updates.
- Токен не попадает в URL, логи или репозиторий.
- Анализатор и все тесты проходят без ошибок.
